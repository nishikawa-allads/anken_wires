# anken_wires

新規案件の広告・計測導線を整理し、既存案件の導線変更をバージョンとして保存するためのプロジェクトです。
質問への回答から基本導線を自動生成し、Miroのようなキャンバス上で必要な箇所だけ手動調整できることを目指します。

初期実装として、導線の自動生成・キャンバス編集・下書き保存・バージョン保存・履歴閲覧が利用できます。
Web・アプリ・電話・LINEを別々の図にせず、選択した計測を1つのキャンバスで確認します。電話は参考構成を生成し、アプリの具体的な経路は確認事項として同じ図に記録します。

## 目的

- 新規案件の流入経路、タグ発火、CV計測先、ポストバック先を見える形にする。
- 標準的な導線を質問から生成し、ノードや矢印を毎回描く手間を減らす。
- 既存案件の導線を変更する際に、変更前後の状態と変更理由を残す。
- Web・アプリ・電話・LINEが併存する案件でも、共通の流入元・LPと各計測の関係を1つの図で整理する。

想定利用者は、案件の立ち上げや広告・計測導線の設計、確認、変更を担当する人です。

## 基本となる導線

入稿経路は案件共通の設定ではなく、メディアラインごとに設定します。
同じ案件内で直メディアとASP経由を混在させ、それぞれの入口から共通のLPへ合流できます。

### 直メディア・Web計測

```text
メディアライン（AA入稿URL）
  ── affnmsid ──> LP（LPタグ発火）
  ──> サンクス（CVタグ発火）
  ──> ALLADiN（CV発生）
```

### ASP経由・Web計測

```text
メディアライン（ASP入稿URL）
  ──> AA入稿URLへリダイレクト
  ── affnmsid ──> LP（LPタグ発火）
  ──> サンクス（CVタグ発火）
  ──> ALLADiN（CV発生）
```

### ASP経由・CLポストバック

```text
メディアライン（ASP入稿URL）
  ──> AA入稿URLへリダイレクト
  ── affnmsid ──> LP（LPタグ発火）
  ──> サンクス（CVタグは原則使用しない）
  ──> CLの計測ツール（CV発生）
  ── ポストバック ──> ALLADiN（CV発生）
```

CLポストバックの場合、サンクスのCVタグは「使用しない」を初期値とします。
例外を扱えるように、案件ごとに使用有無、タグの送信先・役割を変更できる設計にします。
上記の矢印は業務上の流れを簡略化したものです。キャンバスでは、画面遷移と計測通信を区別します。

### 1つの図で扱う分岐

Web・電話・LINEは、共通のメディアラインとLPから分岐させます。共通のALLADiNも同じ図に配置します。
電話計測を選ぶと、参考構成として次の経路と情報連携を生成します。

```text
LP → Call Data Bank → Call Tracker → コールセンター
        └ 通話開始記録 ── API・架電データ ──> ALLADiNデータ取得バッチ → ALLADiN
LP ── 表示番号・LP URL（affnmsid） ──> Call Data Bankの記録
Call Tracker ── 通話開始検知 ──> Call Trackerの記録
```

これは提供資料に基づく参考構成です。CV成立条件、番号管理、取得・通知方法は案件ごとに確認し、未確定の状態を保存できます。
LINEを選ぶと、LPからLINE友だち追加への経路を表示します。成果の通知先は未確認のまま自動接続しません。
LINE友だち追加とアプリ計測は別の項目です。アプリは具体的な経路を推測せず、確認事項ノードを同じ図に置きます。

## 利用の流れ

1. 新規案件か既存案件かを選択します。既存案件では、対象案件と変更元のバージョンを選びます。
2. 案件共通のCLポストバック有無と計測種別に回答し、選択した計測を1つにまとめた基本導線を生成します。
3. 初期作成される「メディアライン1」を選択し、詳細設定で名前と入稿経路（直メディア／ASP経由）を設定します。
4. 必要に応じてメディアラインを追加します。各メディアラインで異なる入稿経路を選択でき、名前の変更・削除もできます。
5. URL・タグ・識別子・計測先を補い、必要に応じて位置や注記を調整します。キャンバス右上から拡大表示や接続の選択ができます。
6. 未設定事項を確認し、変更理由を添えてバージョンを保存します。既存案件の変更では、保存済みの版を残して新しい版を作成します。

| 案件作成時の質問                                 | 回答・入力                             |
| ------------------------------------------------ | -------------------------------------- |
| 新規案件か                                       | 新規／既存。既存の場合は対象案件を選択 |
| CLの計測ツールからのポストバックでCVを受け取るか | 受け取る／受け取らない                 |
| どの計測が存在するか                             | Web／アプリ／電話／LINEの複数選択      |

| メディアラインごとの設定 | 内容                           |
| ------------------------ | ------------------------------ |
| メディアライン名         | 導線上に表示する名前           |
| 入稿経路                 | 直メディア（ASPなし）／ASP経由 |

入稿経路を変更しても、ほかのメディアラインの経路は変更しません。

計測種別を増やしてもキャンバスを切り替えず、1つの図内に分岐や確認事項を追加します。
電話の参考構成やアプリ・LINEの未確定事項を、汎用仕様が確定したものとして扱いません。AFADなど資料に登場するツールや実URL・電話番号を、全案件の固定値にはしません。

## 編集・履歴の方針

- 標準的な構造は質問回答から生成し、手動編集は位置調整や注記など必要な範囲に絞ります。
- 回答変更で導線を再生成する際は、手動入力が消える箇所を事前に確認できるようにします。
- 保存済みバージョンには、案件の質問回答、メディアラインごとの設定、全計測を含む単一グラフ、配置、注記、変更理由をまとめて残します。
- 保存済みバージョンを上書きせず、過去の状態を参照できるようにします。

このツールで扱うのは導線の設計と履歴です。広告配信設定の変更、実際のタグ配信、リダイレクト、ポストバック送信は初期開発の対象外とする案です。
図に「タグ発火」「CV発生」と表示しても、実環境での動作を検証済みであることは意味しません。

## セットアップと起動

Node.js 22.13以降とnpmが必要です。開発時はUIとAPIをまとめて起動します。

```sh
npm ci
npm run dev
```

[http://127.0.0.1:5173](http://127.0.0.1:5173) を開いてください。APIは `127.0.0.1:3001` で起動します。
終了は起動したターミナルで `Ctrl+C` です。

ビルド済みの画面とAPIを同じポートで使う場合は、以下を実行します。

```sh
npm run build
npm start
```

この場合の画面は [http://127.0.0.1:3001](http://127.0.0.1:3001) です。

## 保存と履歴

- データは `data/anken-wires.sqlite` に保存します。ブラウザーのストレージを消しても、DBが残っていれば再表示できます。
- 手動編集後は「下書き保存」を押してください。自動保存は行いません。未保存のまま移動する場合は確認を表示します。
- 左側の「図全体の注記」から図全体の補足情報を確認・編集できます。旧保存版の図単位メモもここにまとめて表示します。保存済み版では閲覧のみです。
- 「バージョン保存」で変更理由を記入すると、案件全体の導線を新しい版として保存します。未設定項目があっても、その状態を残せます。
- 「変更履歴」から保存時点の導線を閲覧できます。「この版から編集」で、その内容を元に新しい下書きを作れます。
- 保存済み版の内容は変更しません。同時更新がある場合は、古い内容での保存を拒否して再読込を案内します。
- 旧形式1・2の保存版は書き換えません。過去版の表示では、保存されていた各導線を表示用に1つの図へまとめます。旧下書きや旧版を元に編集するときだけ、設定・手動調整を引き継いだ新形式3のコピーを作ります。
- 右上のダウンロードボタンから、案件と履歴をJSONで出力できます。JSONの取り込み機能は未実装です。

DBの保存先は `DATA_DIR`、APIのポートは `PORT`、開発画面のポートは `WEB_PORT` で変更できます。
開発画面のAPIプロキシは `PORT` に合わせて接続先を切り替えます。
DBをバックアップする場合はサーバーを終了してから `data/` ディレクトリ全体をコピーしてください。

この初期実装は認証のないローカル利用向けです。複数端末での共有、権限管理、公開配置は未実装です。

## 検証

```sh
npm test                 # 導線生成・入力検証・SQLite保存・競合・ロールバック
npm run build            # 型検査と画面のビルド
npx playwright install chromium  # ブラウザーテストの初回準備
npm run test:e2e          # 案件作成・編集・再生成・履歴の操作確認
```

ブラウザーテストは通常の保存先と別の `.context/e2e-data/` を使用します。
テスト用の画面は5174、APIは3002ポートで起動するため、通常の開発サーバーと並行して検証できます。
